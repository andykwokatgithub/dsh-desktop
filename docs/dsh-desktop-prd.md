## 1. 项目背景与目标

### 1.1 背景
DeepSeek Harness（`dsh`）命令行工具提供 `dsh web` 命令来启动 Web UI 界面（默认地址 `http://127.0.0.1:3080`），但默认会在系统浏览器中打开新标签页。对于高频使用场景，用户更偏好独立的桌面应用窗口，且希望避免误操作导致打开多个重复窗口或浏览器标签页堆积。

> **已核实的实现事实（依据 `@deepseek-ai/dsh` 源码）**
> - `dsh web` 是 `dsh --profile web` 的合法别名；`--no-open` 可用于抑制自动打开浏览器。
> - `dsh web` 启动的是**完整 Harness 运行时**（加载 webserver、API 网关、workspace、前端 dist 等），是一个**长驻服务进程**，而非轻量后台服务。
> - 默认端口 `3080` 可由 web 配置（`cordis.patch.yml` 中 `ctx.webStartup.port ?? 3080`）确认；`--host 0.0.0.0` 被显式拒绝（出于安全），默认绑定 `127.0.0.1`。
> - 浏览器信任栅栏信任 loopback IP 字面量（`127.0.0.1:<port>`），因此 WebView2 以 `http://127.0.0.1:3080` 访问时 `/api` 可正常放行。

本"包装器（Wrapper）"只负责**窗口管理、服务生命周期、单实例防重**，并非复制或替代 Harness 本体。

### 1.2 目标
开发一款基于 **Go + WebView2** 的 Windows 桌面壳程序（Wrapper），实现以下核心能力：

- **无缝嵌入**：通过 WebView2 将 `dsh web` 提供的 Web UI（`http://127.0.0.1:3080`）以原生桌面窗口形式呈现。
- **服务生命周期管理**：自动检测 `dsh web` 后端服务状态，未运行则自动静默启动（带 `--no-open` 参数），等待服务健康后再渲染界面；复用前对既有服务做健康校验，避免复用到陈旧/僵死实例。
- **单例模式（防重复）**：确保系统只有一个应用实例在运行。若用户重复点击启动，自动激活并置顶已有窗口，而非创建新窗口。
- **资源边界声明**：本 Wrapper（Go + WebView2 窗体）资源占用轻量；真正的资源开销来自其托管的 `dsh` Harness Node 进程（详见 §4 非功能性需求）。

## 3. 功能需求详细说明

### FR-01：服务状态检测与自动启动
- **优先级**：P0
- **描述**：应用启动时，通过**端口探测 + HTTP 健康校验**双重判据判断 `dsh web` 服务是否已健康运行。
- **逻辑**：
  1. **健康校验**：向 `http://127.0.0.1:3080/` 发起 GET。dsh web 现在会为 Web UI 生成**每次进程唯一的启动 token**(访问地址形如 `http://127.0.0.1:3080/?token=…`)并做浏览器认证,因此对无 token、无 cookie 的裸 GET `/` 返回 **HTTP 401**(`dsh web authentication required;…`)而非 200。健康校验据此**识别 dsh web 的认证边界**:返回 200(有效 cookie/关闭认证)或 303(token→cookie 交换)即为健康;返回 **401 且响应体带 `dsh web` 签名**时同样判定为健康(证明端口上确实是 dsh web,而非其它进程)。TCP 端口可连但不回 dsh-web 信号 ⇒ 判定为**陈旧/僵死或非 dsh 服务**。
  2. 若服务未健康运行：
     - 若端口被**非 dsh 进程**占用：直接报错并提示端口冲突，**不尝试重启**（重启无法释放被占端口）。
     - 若为 `dsh` 服务但已僵死：按 §FR-04 清理后重新启动。
     - 否则：执行 `dsh web --no-open` 启动后台服务。
  3. **就绪判定**：轮询健康校验（**每 500ms 一次**），整体设置 **冷启动超时 30 秒**；作为补充信号，可同时捕获 `dsh web` 子进程 stdout 中的 `dsh web: <url>` 就绪行。
  4. 若超时仍未就绪，应用显示错误页并退出，提示用户检查 `dsh` 安装或 Node.js 环境。
- **异常处理**：
  - `dsh` 命令不存在：捕获 `exec` 异常，给出友好报错（见 §7）。
  - **Windows spawn 细节**：全局安装的 `dsh` 通常是 `.cmd`/`.ps1` shim（npm 全局 bin）。Go 的 `os/exec` 不会自动按 PATHEXT 解析 `.cmd`，因此**须通过 `cmd /c dsh web --no-open`** 启动，或显式解析出真实脚本路径；同时正确继承 `PATH`、`DSH_HOME` 及用户环境变量（它启动的是完整 Harness，依赖用户配置）。

### FR-02：WebView2 嵌入式窗口渲染
- **优先级**：P0
- **描述**：使用 WebView2 控件创建桌面窗口，加载目标地址。
- **规格**：
  - 窗口标题：`DeepSeek Harness`（**仅用于显示**；单实例定位不依赖标题，见 FR-03）。注意 WebView2 可能随页面 `<title>` 更新标题，需在页面加载完成后按需 `SetTitle` 复核。
  - 默认尺寸：`1200 x 800` 像素；支持最小化、最大化、关闭等标准系统按钮。
  - **加载态/错误态**：服务未就绪时先加载一个**本地 `loading.html`** 占位页；服务健康后再跳转。冷启动(spawn 的 dsh)时用 `WaitHealthy` 从 `dsh web: <url>` 就绪行解析出的**认证 URL(含启动 token)** 执行 `Navigate`,以完成 token→cookie 交换并加载真实 UI;复用路径直接 `Navigate` 到 `http://127.0.0.1:3080`,由 WebView2 持久化 cookie(位于 `%APPDATA%\dsh-desktop.exe`)完成授权。健康校验持续失败时显示**可重试的错误页**(区分"服务启动中 / 端口冲突 / dsh 未安装 / WebView2 未安装")。
  - **导航白名单**：仅允许加载规范本地源 `http://127.0.0.1:3080`；拦截指向**外部域名、`mailto:`、外部 `http(s)`** 的导航并将其交给系统默认浏览器处理（防止外部页面被信任栅栏 / 脚本上下文错误处理）。
  - **开发者工具与右键菜单**：默认关闭；提供配置开关（`devtools`、`context_menu`），可在后续迭代暴露。当前版本以"安全默认"为原则。

### FR-03：全局单例与窗口激活（防重复）
- **优先级**：P0
- **描述**：利用 Windows 全局互斥体（Mutex）实现进程互斥，防止多开。
- **详细逻辑**：
  1. 应用启动时尝试创建互斥体（命名：`Local\DSHDesktopApp`）。
     - **命名空间取舍**：默认用 `Local\`（会话内互斥）。`Global\` 会跨会话，可能导致多用户 / RDP 场景下第二个用户无法启动，需在"严格全局唯一"与"多会话可用"之间权衡；本期采用 `Local\`，并记录该取舍。
  2. 若创建失败且错误码为 `ERROR_ALREADY_EXISTS`，判定已有实例运行。
  3. 此时不创建新窗口，而是**激活已有窗口**：
     - 通过**唯一窗口类名**（如 `DSHDesktopAppMainWindow`）用 `FindWindowW(className, NULL)` 定位窗口（**不用窗口标题匹配**，避免标题随页面 `<title>` 变化导致漏匹配 / 误匹配）。
     - 若窗口最小化，调用 `ShowWindow(SW_RESTORE)` 恢复。
     - **激活**：发送自定义注册消息 `RegisterWindowMessage("DSHDesktopApp.Activate")` + `SendMessageTimeout`，让已存在窗口自行置顶；已存在窗口收到后执行 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`。**前台激活限制**：Windows 限制后台进程直接抢占前台，需叠加 `AllowSetForegroundWindow` / `AttachThreadInput` 等回退，或依靠消息驱动的"窗口自激活"来规避。
  4. 激活完成后，新启动进程立即退出（无痕操作）。

### FR-04：服务生命周期管理
- **优先级**：P0
- **描述**：明确 `dsh web` 后端子进程与 Wrapper 窗口的**归属关系**，以及停止 / 恢复策略。
- **设计决策（默认方案）**：采用"**服务持久化复用**"——关闭 WebView2 窗口时**默认保留** `dsh web` 子进程，后续再次启动 Wrapper 时复用该服务，避免重复冷启动。
  - **复用前健康校验**：每次启动先对 `3080` 做健康校验（见 FR-01）。若端口开放但健康校验失败 ⇒ 判定为陈旧/僵死服务，**清理整棵进程树后重新启动**（`dsh` 的 Harness 可能派生子 agent / workflow worker 线程，需按进程树一并终止，而非只杀父进程）。
  - **主动停止**：`dsh` 提供"退出"入口（托盘 / 菜单），并提供一个配置项决定"关闭窗口时是否同时停止后端服务"（默认停止服务为**关闭**，即保留），亦可在"退出"时选择"同时停止后台服务"。
  - **版本 / 配置变更防护**：若用户升级 `dsh` 或改动配置，持久化的旧实例可能不匹配；健康校验可加入"进程启动时间戳 / `--version` 差异"作为可选的重新启动信号。
- **可切换方案（备选，写入配置项）**：若希望"窗口关闭即完全退出"，可切换为"Wrapper 拥有子进程，窗口关闭即清理整棵 `dsh` 进程树"。两种方案仅影响资源驻留与二次启动速度，不影响窗口/单实例逻辑。

## 4. 非功能性需求（NFR）

| 分类 | 要求 |
| :--- | :--- |
| **平台兼容性** | 仅支持 Windows 10 (**Build 17134/1803+**) 及 Windows 11。依赖系统已安装 WebView2 Evergreen 运行时（Windows 11 预装；Windows 10 需手动安装）。 |
| **启动性能** | **热启动**（服务已在运行）：从双击到界面可交互 ≤ **3 秒**。**冷启动**（服务未运行）：窗口与加载态 ≤ 3 秒；服务健康 → WebView 跳转到可交互 ≤ **30 秒**（超时即失败，见 FR-01）。 |
| **资源占用** | **仅指 Wrapper 本体**（Go + WebView2 窗体）：内存 < 150MB（闲置），CPU < 1%（闲置）。其托管的 `dsh` Harness Node 进程资源**单列、不纳入此指标**（见 §1.2 资源边界声明）。 |
| **可靠性** | 服务启动超时保护（30s）+ 健康校验重试；端口被非 dsh 进程占用时明确报错且**不重启**；避免因网络栈延迟导致的假性崩溃。 |
| **安全** | 仅允许加载规范本地源 `http://127.0.0.1:3080`；拦截外部导航；默认禁用开发者工具与右键菜单；`--host 0.0.0.0` 不可用（顶层 dsh 已拒绝）。由于 `/api` 具备执行代码/读写 workspace 的能力，窗口必须依托 dsh 的浏览器信任栅栏，禁止加载任何不被信任的来源。 |

**Node.js 版本说明**：`dsh` 顶层包**未声明自身 `engines`**；`22.19.0+` 来自传递依赖下限（`@earendil-works/pi-ai` 要求 `>=22.19.0`，`commander` 要求 `>=22.12.0`）。实现时应以**实际安装的 `dsh` 所依赖的下限**为准，避免写死一个非官方值。

## 5. 技术架构与依赖

- **开发语言**：Go 1.21+
- **核心依赖库**：
  - `github.com/webview/webview_go`：WebView2 绑定与窗口管理（Windows 上基于 WebView2/Edge Chromium；注意其依赖 **CGO**，**难以跨平台交叉编译**）。
  - `golang.org/x/sys/windows`：调用底层 Windows API（Mutex、窗口激活、消息等）。
- **外部环境依赖**：
  - 全局安装 `dsh` 命令行工具（`npm i -g @deepseek-ai/dsh`），且 `dsh`、`node` 均在 `PATH` 中。Windows spawn 需处理 `.cmd`/`.ps1` shim（见 FR-01）。
  - Node.js 下限以满足已安装 `dsh` 的依赖要求为准（见 §4 说明）。
  - WebView2 Evergreen 运行时（Windows 11 预装，Windows 10 需手动安装）。
- **工程与分发**：
  - 因 `webview_go` 依赖 CGO，**跨平台交叉编译困难**；Windows 构建需在本机/Windows 环境完成。
  - 产物需随包携带 **WebView2Loader.dll**（或依赖系统 Runtime）。
  - 分发形态：**MSI / 便携版**；建议做**代码签名**以规避 Windows SmartScreen 警告；自动更新列为后续迭代（见 §10）。

## 6. 用户操作流程

### 6.1 正常首次启动流程（冷启动）
1. 用户双击 `dsh-desktop.exe`。
2. 程序创建互斥体；创建窗口并显示 `loading.html` 加载态。
3. 程序对 `http://127.0.0.1:3080/` 做健康校验 → 未服务（端口未监听）。
4. 程序执行 `dsh web --no-open`（经 `cmd /c` 解析 shim），轮询健康校验等待就绪。
5. 健康校验返回 HTTP 200 后，WebView2 跳转加载 DSH UI。
6. 用户看到交互界面。

### 6.2 热启动流程（服务已在运行）
1. 用户双击 `dsh-desktop.exe`。
2. 健康校验通过 → 复用现有服务，直接跳转加载 DSH UI（快速进入，≤3s）。

### 6.3 重复启动流程（窗口已存在）
1. 用户再次双击 `dsh-desktop.exe`。
2. 程序创建互斥体 → 发现已存在实例。
3. 程序以唯一窗口类定位现有窗口，发送激活消息使其置顶；若最小化则 `ShowWindow(SW_RESTORE)`。
4. 当前双击的进程自动退出，不占用额外内存。

## 7. 边界情况与异常处理

| 异常场景 | 处理策略 |
| :--- | :--- |
| **`dsh` 未安装 / PATH 未包含** | 捕获 `exec`/`cmd /c` 失败，弹窗或日志提示"未找到 dsh 命令，请检查是否已全局安装（npm i -g @deepseek-ai/dsh）"。注意 Windows 下需先正确解析 `.cmd` shim 再判断。 |
| **端口被非 dsh 程序占用** | 健康校验失败（TCP 可连但非 HTTP 200 / 非 dsh）⇒ 视为端口冲突，**报错提示，不重启**；引导用户释放端口或改用其它端口。 |
| **`dsh` 服务僵死（端口开放但健康校验失败）** | 按 FR-04 清理整棵进程树后重启服务。 |
| **WebView2 未安装 / Runtime 缺失** | `webview.New` 抛出致命错误，程序捕获并提示下载 WebView2 Evergreen 运行时。 |
| **服务启动超时** | 等待 30s 后显示错误页并退出，日志记录超时错误；不残留半启动的子进程。 |
| **窗口句柄获取失败（唯一窗口类匹配不到）** | 互斥体存在但窗口找不到（进程挂起/僵尸 / 在不同会话桌面），程序记录日志并退出，防止无限循环。 |
| **前端尚未就绪（服务已监听但页面/`/api` 未就绪）** | 通过"健康校验 + 加载态"过渡，先显示加载页，待健康后跳转；避免白屏或 `ERR_CONNECTION_REFUSED`。 |
| **外部链接 / 下载触发** | 外部 `http(s)`/`mailto:` 导航交给系统默认浏览器；文件下载按需由 WebView2 处理或提示。 |

## 8. 验收标准

- [ ] **AC-01**：首次运行（服务未启动），程序自动启动服务、健康校验通过后界面正常显示；期间窗口先显示加载态，无白屏。
- [ ] **AC-02**：连续双击两次 `.exe`，只显示一个窗口；第二个进程自动退出，原有窗口被激活并置顶（即使窗口最小化）。
- [ ] **AC-03**：关闭 WebView2 窗口后，`dsh` 子进程按默认策略保留；重新打开程序时执行**健康校验**（非仅端口探测）后复用该服务；若服务已僵死（端口开放但健康校验失败），程序清理并重启。
- [ ] **AC-04**：窗口标题栏显示 `DeepSeek Harness`。
- [ ] **AC-05**：在 `dsh` 未安装/不可解析的环境下运行，程序给出明确错误提示，而非直接崩溃（Windows 下正确处理 `.cmd` shim）。
- [ ] **AC-06**：在端口被非 dsh 程序占用时，程序明确提示端口冲突，**不尝试重启**（避免无效动作/卡顿）。
- [ ] **AC-07**：导航到外部域名时被拦截并交由系统浏览器处理；开发者工具与右键菜单默认不可用。

- **跨平台支持**：适配 macOS (WkWebView) 和 Linux (GTK WebView)；需按平台调整服务启动方式（`dsh web` 在不同平台的行为差异）。
- **偏好设置**：增加"开机自启""窗口置顶""暗黑模式跟随系统""关闭窗口时是否停止后端服务"等选项。
- **托盘驻留**：关闭窗口时最小化到系统托盘，提供"退出""停止服务/重启服务"入口。
- **自动更新与代码签名**（含 SmartScreen 规避）。
- **窗口尺寸/位置记忆**；**多标签/多会话快速切换**的便捷入口。
- **开发者工具 / 调试开关**的界面化配置。

## 11. 成功度量建议
- **热启动时间**：双击 → 界面可交互 ≤ 3s（测量口径：进程启动 + 健康校验 + WebView NavigationCompleted）。
- **冷启动时间**：窗口出现 ≤ 3s；服务就绪 → 可交互 ≤ 30s。
- **激活成功率**：重复启动时对既有窗口的激活/置顶成功比例（含最小化恢复）。
- **异常退出率**：因健康校验失败、端口冲突、子进程残留等导致的异常退出比例。
